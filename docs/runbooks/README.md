# Runbooks

Before production, implement and test owner-assigned procedures for:

- API/worker deployment rollback
- failed migration and database restore
- queue backlog, poison messages, and dead-letter recovery
- object storage or signed-URL incident
- connector token compromise or platform outage
- AI provider outage, unsafe output, or unexpected spend
- security incident, evidence legal hold, and data deletion
- Clerk authentication or webhook delivery outage

Each runbook must include dashboards/commands, escalation path, decision points, and post-incident follow-up.
